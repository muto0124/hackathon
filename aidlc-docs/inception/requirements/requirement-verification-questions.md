# Requirement Verification Questions

AI-DLC Inception の Requirements Analysis で確認した質問と回答を、後続成果物へ追跡できる形で整理する。

## Q-001: 意思決定代行の対象領域

低リスクな日常判断のうち、T-AI-DA が最初に代行すべき領域はどこか。

[Answer]:
MVP では、食事、服装、日々の予定提案、買い物候補、週末または夜の過ごし方を対象にする。仕事後の日常的な意思決定疲れを減らすことを中心に置き、高額購入、医療、法務、雇用、重大な人間関係の判断には踏み込まない。

## Q-002: MVP の入口

ユーザーが T-AI-DA を使い始める主要な入口は何か。

[Answer]:
MVP の入口は、朝の生活プランとオンデマンドの即決ボタンにする。朝は一日の低リスクな生活判断をまとめて提案し、日中や仕事後は小さな迷いに対して一択回答を返す。

## Q-003: サービス人格

T-AI-DA はどのような口調と人格でユーザーに接するべきか。

[Answer]:
過保護で、少し皮肉っぽい執事として振る舞う。ユーザーを責めず、判断疲れを肩代わりする一方で、「その程度の迷いは私が片付けます」のように軽い皮肉を含む。

## Q-004: 意思決定代行の強さ

T-AI-DA はどの程度まで判断を代行してよいか。

[Answer]:
怠惰レベルに応じて、提案型、半自動型、低リスク自動決定型を切り替える。初期状態では理由付き提案を中心にし、ユーザーの許容度と対象領域の安全性に応じて、準備や低リスクな決定の自動化を段階的に強める。

## Q-005: 利用する文脈データ

MVP で判断材料として利用する文脈データは何か。

[Answer]:
天気、予定、好み、位置情報、予算を MVP の基本文脈データとする。将来は購入履歴、カレンダー連携、健康ログ、関係性の好みなどを扱えるが、重大な影響を持つ判断には明示的な制限と承認を設ける。

## Q-006: 対象ユーザー

最初に価値を届ける対象ユーザーは誰か。

[Answer]:
意思決定疲れを抱えた一人ビジネスパーソンを対象にする。特に、仕事では判断を重ねているが、退勤後や朝の生活判断にはもう頭を使いたくないユーザーを想定する。

## Q-007: 象徴的な体験

審査員に伝えるべき T-AI-DA らしい体験は何か。

[Answer]:
朝に「今日の生活プラン」を受け取り、迷った瞬間には即決ボタンで一択回答を得る体験を象徴にする。ユーザーが判断を委任するほど怠惰レベルが上がり、T-AI-DA が先回りして準備する範囲が広がる。

## Q-008: 実行代行の範囲

MVP では実行支援や代行をどこまで行うか。

[Answer]:
MVP では、買い物リスト、店舗候補、移動ルート、注文リンクなどの準備支援までを中心にする。実購入、予約、送信、契約など外部に影響する確定操作は、将来スコープとして明示承認を必要とする。

## Q-009: サービス名

サービス名は何か。その意味は何か。

[Answer]:
サービス名は T-AI-DA とする。「怠惰」と「AI」を組み合わせた名前であり、ユーザーが低リスクな判断を委任するほど怠惰レベルが上がる意思決定 OS / Life OS の方向性を表す。

## Q-010: 自動決定しない領域

T-AI-DA が自動決定してはいけない領域は何か。

[Answer]:
高額な購入、医療診断や治療判断、法務、契約、雇用、退職、別れに関する判断、金銭、健康、法律、人間関係に重大な影響を与える判断は自動決定しない。検出した場合は、承認要求、専門家相談の案内、または拒否に切り替える。
